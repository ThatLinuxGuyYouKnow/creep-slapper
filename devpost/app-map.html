Scope-Creep Slapper 9000 — App Map

Snapshot of fe43025. Paste an over-ambitious hackathon idea, add context, hit SLAP — back comes a keep list, an MVP checklist, and struck-through creeps. Single page, no accounts, no saved history.

How a slap flows

Browser holds only UI state. Every key lives server-side in api/*. Link text and transcripts feed one prompt built in src/lib/prompt.ts.

Reference route (2 stops)

  1. src/App.tsx → handleSlap: gathers dump + cached link text, warns and proceeds on link failure, posts to /api/slap. Search anchor: LINK CONTEXT.
  2. api/slap.ts → handler: validates input, calls DeepSeek with buildSlapPrompt, validates keep/checklist/creeps shape before returning. Search anchor: isStringArray.

To change this, start here

  • Slap tone or rules → src/lib/prompt.ts (buildSlapPrompt), re-run a slap to see it.
  • Result layout → src/components/SlapResult.tsx.
  • Demo seeds → src/lib/demo-seeds.ts (pure data, no service).
  • New server behavior → api/*.ts, then bundle-check with npx esbuild api/<name>.ts --bundle --platform=node.

A practice to reuse

Gate every step on runnable evidence. Each build slice here carried its own mechanical check (devpost/checklist.md → Verify (mechanical)): the esbuild-bundle harness proved api/* handlers without deploying, and forced-failure runs (bad key → 500, empty dump → 400) proved the warn paths. When Firecrawl returned 401 on both endpoint versions, the identical error distinguished a bad key from a wrong endpoint — one variable tested, one conclusion. Reuse: before moving any agent-built step forward, name the one command that proves it and the failure case that proves the fallback.
